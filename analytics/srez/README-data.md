# СРЕЗ — данные и расчётное ядро

Все 90 заказов в `data.js` и `sample-sales.csv` вымышлены. Это детерминированный пример магазина сумок, рюкзаков и аксессуаров: 30 строк за каждый месяц с июля по сентябрь 2026 года. Одна строка — один оплаченный заказ или операция возврата. Реальные продажи, личные данные и API не используются.

## Контракт CSV

Заголовок: `id,date,product,category,channel,status,quantity,revenue,cost`.

| Поле | Правило |
|---|---|
| id | Уникальная непустая строка, до 100 символов |
| date | Реальная календарная дата YYYY-MM-DD |
| product | Непустая строка, до 200 символов |
| category | Сумки / Рюкзаки / Аксессуары |
| channel | Сайт / Маркетплейс / Розница |
| status | Оплачен / Возврат |
| quantity | Целое число 1–999 |
| revenue, cost | Сумма **за всю строку**, в рублях; 0–10 000 000 000, максимум две цифры после точки |

Порядок столбцов произвольный; состав строго задан, без неизвестных или повторных заголовков. Поддерживаются запятая и точка с запятой, UTF-8 BOM, CRLF/LF, поля в кавычках, удвоенные кавычки и переносы внутри поля. Пустые строки пропускаются. Лимит — 1 МиБ текста UTF-8 и 5000 заказов. Десятичный разделитель — точка; разделители тысяч и обозначение валюты исключены.

Ошибка указывает физическую строку файла и поле. `parseCSV()` возвращает весь проверенный массив либо выбрасывает исключение; частичного результата нет. В интерфейсе заменять текущий набор только после успешного завершения `parseCSV()`. Отсутствие записей в CSV считается ошибкой, чтобы пустой файл случайно не заменил набор данных.

## Формулы KPI

- **Чистая выручка** (`revenue`): сумма выручки оплаченных строк минус сумма возвратов.
- **Валовая прибыль** (`profit`): сумма `(revenue − cost)` оплаченных строк минус такая же величина возвратов. Возврат также обращает себестоимость. Это модель демонстрационных данных, не бухгалтерская отчётность.
- **Оплаченные заказы** (`paidOrders`): количество строк со статусом «Оплачен»; `quantity` означает число единиц внутри заказа.
- **Средний чек** (`averageOrder`): выручка только оплаченных строк / число оплаченных строк. Возвраты исключены из обеих частей. Если оплаченных заказов нет, результат 0.
- **Возвраты** (`returnAmount`, `returnOrders`): положительная сумма и число строк возвратов.
- **Чистые единицы** (`netUnits`): оплаченные единицы минус возвращённые единицы.

Комиссии площадок, реклама, налоги, зарплаты и расходы на доставку не моделируются и не вычитаются. Валовая прибыль не называется чистой. Цена строки уже учитывает количество: дополнительного умножения на `quantity` нет.

Деньги суммируются в целых копейках; средний чек и процент изменения округляются до двух знаков. Ограничения размера и суммы сохраняют целочисленную точность. Отрицательные итоговые выручка и прибыль допустимы: например, в выбранном периоде могут быть только возвраты или убыточные продажи.

## API классических скриптов

Подключение: `data.js`, затем `core.js`, затем интерфейс приложения. Скрипты не требуют сборщика, npm, сервера расчётов или внешних библиотек.

```js
const all = SrezData.rows;
const filters = { from: '2026-09-01', to: '2026-09-30', channel: 'all', category: 'all', query: '' };
const selected = SrezCore.filter(all, filters);
const kpi = SrezCore.summary(selected);
const chart = SrezCore.series(selected, filters.from, filters.to); // day по умолчанию
const weekly = SrezCore.series(selected, filters.from, filters.to, 'week');
const byChannel = SrezCore.group(selected, 'channel');
const table = SrezCore.sort(selected, 'date', 'desc');
const comparison = SrezCore.comparePeriod(all, filters);
const imported = SrezCore.parseCSV(csvText); // выбрасывает Error при любой ошибке
const exported = SrezCore.toCSV(selected, ',', true); // защитный режим для Excel/Sheets
```

- `filter` включает обе граничные даты. Пустое значение, `all` или `Все` означает все каналы/категории. Поиск по `id` и `product` регистронезависимый. Исходный массив не меняется.
- `summary` возвращает `revenue, profit, paidRevenue, paidOrders, averageOrder, returnAmount, returnOrders, netUnits`.
- `series` возвращает массив `{date, ...summary}` по возрастанию дат, включая пустые дни с нулевыми показателями. В режиме `week` интервалы по семь дней отсчитываются **от выбранной даты начала**, а не от календарного понедельника. Последний интервал может быть короче. Максимальный диапазон — 3653 дня включительно.
- `group` поддерживает `channel, category, status, product`; результат `{label, ...summary}` отсортирован по чистой выручке убыванию. Отсутствующие группы не добавляются. Все показатели знаковые.
- `sort` поддерживает `date, revenue, id` и `asc/desc`, возвращает копию массива. Выручка сортируется со знаком: возврат — отрицательная сумма, как в таблице интерфейса.
- `comparePeriod` возвращает `current, previous, previousFrom, previousTo, changes`. Предыдущий период — равное количество дней непосредственно перед текущим, UTC. Сравнение сентября 1–30 — **август 2–31**, а не календарный август. Изменение `(current − previous) / abs(previous) × 100`; при нулевом предыдущем значении — `null`, в UI показывать «—», а не фиктивный процент. Фильтры категории, канала и поиска сохраняются в обоих периодах.
- `toCSV` по умолчанию сохраняет точные строковые значения для round-trip. Параметр `spreadsheetSafe=true` добавляет апостроф перед строкой, начинающейся с `=`, `+`, `-`, `@`, табуляции или CR; это нейтрализует формулы при открытии в электронных таблицах. Данные с таким префиксом при повторном импорте сохраняют защитный апостроф. Числовые ячейки остаются числами.
- Внутренние API `summary/filter` ожидают уже проверенные строки из `SrezData` или `parseCSV`. Названия товаров — недоверенный текст; интерфейс обязан выводить через `textContent` или HTML-экранирование, не через необработанный `innerHTML`.
